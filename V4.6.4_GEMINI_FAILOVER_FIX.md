# v4.6.4 — Gemini failover status parsing fix

## Problem addressed

The Google GenAI SDK may surface an upstream 503 as a message such as `Retryable HTTP Error: Service Unavailable` without a numeric `status` field. The previous router only inspected numeric status properties, classified this response as unknown, and stopped after the first model. This matches the v4.6.3 server log where only `gemini-3.8-flash` appeared in the attempted list.

## Changes

- Added a shared Gemini error classifier that reads status codes from direct fields, nested causes, and SDK error text.
- Parses message-only errors including `Service Unavailable` (503), `RESOURCE_EXHAUSTED` (429), and `Not Found` (404).
- Moves to the next configured model on HTTP 404, 408, 425, 429, any 5xx, and recognized network/timeout failures.
- Logs the next model by name so failover progress is visible in the server terminal.
- Replaced the recommended default pool with five distinct current Gemini API endpoints: `gemini-3.8-flash`, `gemini-3.6-flash`, `gemini-3.5-flash-lite`, `gemini-3.1-flash-lite`, and `gemini-3-flash-preview`.
- Added `npm run test:failover`, with regression coverage for 404, 429, all 5xx codes, network timeouts, and invalid credentials.

## Test

Run:

```powershell
npm install
npm run test:failover
npm run dev
```

For a v4.6.3 upgrade, also update the five `GEMINI_*_MODEL` settings in your existing `server/.env`. Copying `.env.example` does not overwrite an existing `.env` file.

## Limits

The router can only try endpoints that the API key/project is authorized to access. Quotas and availability can differ per model and may change. Switching models cannot guarantee success during a provider-wide outage or if the network is offline.

- Models: https://ai.google.dev/gemini-api/docs/models
- API errors: https://ai.google.dev/gemini-api/docs/api-errors
