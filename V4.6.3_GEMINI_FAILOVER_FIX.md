# v4.6.3 — Gemini network failover fix

## Problem addressed
The router only classified HTTP status codes. A network exception such as `TypeError: fetch failed` with `cause.code = UND_ERR_HEADERS_TIMEOUT` has no HTTP status, so the route stopped after the Precision model instead of trying the next model.

## Changes
- Detects common Node/Undici network errors and request timeouts, including nested `cause` values.
- Immediately advances to the next configured distinct model on HTTP 404, 408, 429, 5xx, and network/timeout failures.
- Sets the Google GenAI SDK to one attempt per model so SDK retries do not hold up application-level failover.
- Sets a configurable per-model request timeout, defaulting to 45 seconds (`GEMINI_REQUEST_TIMEOUT_MS`).
- Returns a clearer 503 network error after all configured routes fail.

## Test
Run `npm install` and `npm run dev`. To verify the routing path, watch the server terminal. On the first network failure it should log a line such as `[AI] gemini-3.8-flash unavailable (network/timeout); switching intelligence module.` followed by a request log for the next configured model.

Provider-wide outages, an offline machine, invalid API credentials, or invalid model IDs can still prevent successful AI output. The router will attempt the eligible next routes and report the final error.
